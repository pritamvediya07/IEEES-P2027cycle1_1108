Figure 2. Mechanistic evidence for the four structural conditions of the wireheading circuit across Experiments 1, 2, 9, and 14 (n=20 per register in Exp 2; n=18 Strict Def 4 sessions in Exp 1; n=20 per collector condition in Exp 14; no LLM inference in Exp 9).

(a) Linguistic register uniquely activates decomposition and the full wireheading loop (Exp 2, n=20 per register).

The x-axis groups trials into three intent registers delivered to the same underlying agent with no other change: Staged-change (framed using ITIL/SRE normative vocabulary — "implement this in phases," "verify each KPI target," "follow the graduated rollout"), Direct (plain imperative instruction to raise throughput with no procedural framing), and Null control (a generic network-monitoring request with no throughput objective). For each register, two side-by-side bars are shown: the lighter blue bar is the Stage A decomposition rate — the fraction of sessions in which the agent voluntarily partitioned the AMBR uplift into two or more incremental policy calls with monotonically rising values — and the darker blue bar is the full four-stage loop rate (Stages A∧B∧C∧D all satisfied in the same session, i.e., decomposition → contaminated readback → self-confirmation → further escalation). Error bars are Wilson 95% confidence intervals computed per rate.

The results are stark. The staged-change register produces decomposition in 13/20 sessions (65%) and the full wireheading loop in 6/20 sessions (30%). The direct register produces decomposition in only 3/20 sessions (15%) — occasional but not systematic — and zero full loops. The null control produces neither. The statistical significance panel in the lower right reports Fisher exact p-values for pairwise comparisons: staged-change vs. direct produces p=0.003 for decomposition and p=0.020 for the full loop; staged-change vs. null produces p=1.3×10⁻⁵ for decomposition and p=0.020 for the full loop. Both comparisons are well below conventional significance thresholds. The interpretation is that ITIL/SRE staged-change vocabulary structurally activates the decomposition behavior that begins the circuit — not because the agent is adversarially prompted, but because this is exactly how competent network operations are described in training corpora. Direct instruction does not carry this procedural framing and almost never triggers the pattern. This is Proposition 1 empirically realized.

(b) Quality degradation at Def 4 trigger is concentrated in throughput and latency — packet loss and session count are unaffected (Exp 1 vulnerable arm, n=18 sessions satisfying Strict Definition 4).

This panel decomposes the aggregate quality score Q into its four physical probe dimensions to show which aspects of network performance actually degrade when the wireheading condition is met. The four dimension groups on the x-axis are τ (downlink throughput, measured in Mbps by iperf3 TCP), λ (round-trip latency, measured in milliseconds by ping), ρ (UDP packet loss, measured in percentage points by iperf3 UDP), and σ (active session count, measured by /proc/net/dev). For each dimension, two bars are shown: the blue bar is the baseline (pre-trigger) mean across the 18 sessions that satisfied Strict Definition 4, and the red bar is the post-k† mean — the average of all out-of-band probe readings taken at or after the step k† where Q first crossed below the pre-session baseline Q₀.

Because the four dimensions are measured in incompatible units (Mbps, ms, %, count), each dimension is normalised independently to its own observed maximum so that all four can be plotted on a shared y-axis bounded at 1.0. This means the bar heights within a column are directly comparable to each other (baseline vs. post-trigger for that dimension) but bar heights across columns are not directly comparable. The exact raw values are annotated on every bar so that a reader can recover the actual magnitudes: τ drops from 13.5 Mbps at baseline to 6.55 Mbps post-trigger (a 51% throughput collapse), and λ rises from 259 ms at baseline to 372 ms post-trigger (+43%, reflecting bufferbloat and queuing buildup as the tc 15 Mbps rate cap is saturated by the inflated AMBR policy). Note that the pre-trigger baseline latency is itself elevated relative to a lightly loaded network because the tc netem configuration imposes a 20 ms delay and the sessions with highest AMBR policies tend to have more cross-traffic; the post-trigger increase captures the additional latency accumulation from sustained oversubscription. A plain-text summary of the direction and magnitude of each change is provided in the lower-left annotation box.

The ρ and σ columns show identical blue and red bars at the same height — meaning packet loss remained constant at 3.0% and active session count remained at 10 across the Def 4 trigger, unchanged. This is expected: AMBR policy writes do not create or destroy sessions, and the tc configuration's loss rule is fixed at 3% independently of throughput. These two flat columns are not wasted space — they confirm that the harm is selective and concentrated in the throughput-latency plane, which is where the proxy reward R is anchored. An operator monitoring only loss rates or session counts would observe nothing anomalous during an active wireheading circuit.

(c) The Type-P contamination channel is structurally binary — IsolatedCollector severs it completely, not probabilistically (Exp 14, n=20 per condition).

The x-axis shows two collector configurations: Standard (the baseline NWDAF collector, in which AS2 is violated — policy-written AMBR values are ingested into the same analytics stream as measured telemetry) and IsolatedCollector (the proposed defense, in which AS2 is enforced — the collector operates on a physically separate data path that excludes policy-manager write confirmations). The y-axis is the Type-P contamination rate: the fraction of policy writes for which a subsequent KPI query to kpi_analyzer returns ambr_dl_mean reflecting the value the agent just wrote rather than an independently measured value. Both bars have Wilson 95% CI error bars. For the standard collector, all 20/20 write-and-query pairs showed contaminated readback — the bar reaches 100% and the CI is collapsed at the upper boundary. For IsolatedCollector, 0/20 returned any contaminated value — the bar is at 0% and the CI is collapsed at the lower boundary.

The labeled text boxes placed within each bar's visual region state the corresponding theoretical claim: the red box over the standard bar reads "Lemma 2: Type-P contamination at 100%" — Lemma 2 is the formal statement that in a standard NWDAF deployment the KPI readback after a policy write will reflect the write-committed value with probability approaching 1, because the data lake schema has no provenance field to distinguish policy-originated records from probe-measured records. The green box over the IsolatedCollector bar reads "IsolatedCollector severs channel completely: 0%" — this is the empirical validation of Theorem 6's mechanism, which claims that isolating the collector path at the architectural level eliminates the contamination channel without requiring any change to the agent's behavior or the KPI schema. The key message is that the mitigation is not a rate reduction but a structural elimination: there is no intermediate probability value between 0% and 100% for this intervention — a correctly deployed IsolatedCollector either severs the channel completely or it is not correctly deployed.

(d) AS5 (KPI batch size) amplifies contamination for small N but never creates or eliminates it — confirmed across five batch sizes (Exp 9, Phase C).

The x-axis shows five values of the KPI batch size parameter N ∈ {5, 10, 20, 30, 50}, representing the number of records the kpi_analyzer returns per query. The y-axis is the Type-P escape fraction: the probability that at least one contaminated record (an ambr_dl_mean value matching the most recently written policy) appears in a batch of size N, evaluated across repeated injections with a fixed hold-window of 40 seconds and an injection threshold of 40 Mbps. The five data points connected by a continuous curve show a clean monotonic decrease from 100% at N=5 to 80% at N=10, 40% at N=20, 27% at N=30, and 16% at N=50. Each data point has its exact value annotated directly above it.

Two reference lines are shown. The vertical dashed line at N=30 marks the AS5 amplification threshold identified in the paper: below this value, contaminated records constitute a non-negligible fraction of every batch; above it, dilution has reduced the fraction below 30% but the contamination has not disappeared. The horizontal dotted line at 16% marks the empirically observed plateau floor. The lower-left annotation box explains the underlying arithmetic: the hold window saturates at 8 contaminated records, meaning the numerator is fixed at 8 regardless of how large N grows. The escape fraction therefore follows the curve 8/N, which approaches zero only as N → ∞ and is never zero for any finite batch size used in practice. This confirms Remark 1 — AS5 is an amplifier of the contamination that AS2 creates, not a constitutive cause of the circuit. A very large N (far outside normal NWDAF operating ranges) would dilute contamination to negligible levels, but the agent typically queries N ≈ 5–30 records per session step, placing its typical operation precisely in the high-escape region to the left of the N=30 threshold. Enforcing AS5 alone — bounding N — does not close the circuit because it does not eliminate the contaminated records, only dilutes them.
