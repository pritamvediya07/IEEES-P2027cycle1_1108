## Abstract

Large language model (LLM) based agents are entering 5G/6G network management loops, where they read Network Data Analytics Function (NWDAF) analytics and invoke policy tools that modify core-network state. We show that this read-after-write architecture can cause deployment-time reward hacking. An agent's policy writes can later reappear in analytics as evidence of success, even while independently measured physical-network performance degrades. The failure occurs with a frozen, non-malicious model, uncompromised tools, and benign operator intent.

We formalise this setting as the **Policy-Analytics Language Agent System (PALA)**, which separates agent-visible proxy reward from true network quality. We define **NGN Reward Hacking** as a session-level failure in which a feasible policy sequence achieves higher proxy reward than a non-escalating baseline while producing worse physical-network performance. We identify three interface properties: *stateless per-call feasibility validation*, *provenance-free collector aggregation*, and *per-call oversight*; together, they compose into a closed contamination circuit.

We instantiate PALA on a Release-18-compatible Open5GS/UERANSIM testbed and evaluate it across open-weight and frontier models. Under ITIL/SRE staged AMBR intents, the circuit closes in 27–75% of sessions across the tested models, and NGN Reward Hacking holds in up to 18/30 sessions. We propose **PALA Guardrail**, where IsolatedCollector removes policy-derived analytics from the proxy path, and HedgeTuned budgeting bounds multi-step escalation. The combined guardrail maintains 0/50 operational closures against adaptive prompts with a 5–6% false-rejection cost in our benign corpus. Our results show that this deployment class requires provenance-aware analytics and session-level escalation bounds.

## Quick Start — One Command

```bash
./run_artifact.sh
```

This single command checks **the main-evaluation statistics listed below and every srsRAN
number printed in the paper**, on any Linux or macOS machine with Python 3.10–3.12 (tested
with 3.12; the pinned numpy has no 3.13 wheel, and the script refuses other versions). It
creates `.venv`, installs the dependencies, and runs five stages:

| Stage | What it checks | Expected |
|---|---|---|
| `stored_results` | the stored trial logs and srsRAN result files are present | `PASS` |
| `unit_tests` | tool, collector, and defense logic (on an in-memory MongoDB; no database is contacted) | `26 passed` |
| `trackA_main_evaluation` | the main-evaluation numbers (Tables 2–4, 6, 9, 10A/10C, 11A; Fig. 4a/4c; §6.3 target share; App. G calibration), recomputed from the stored UERANSIM traces; regenerates Figures 3–4 | `All 54 checks PASS` |
| `trackC1_srsran_numbers` | the srsRAN number registry (79 registered numbers) recomputed from raw results, and the 41 srsRAN numbers printed in the paper checked at their printed precision | `PASSED` |
| `trackC1_prompt_provenance` | each experiment used the paper's prompts, corpora, and model | `PASSED` |

It ends with `ALL 5 STAGES PASSED` and exits `0`; any failure exits non-zero and points to
its log. Every stage is logged in `artifact_logs/`, with a summary in
`artifact_logs/SUMMARY.txt`.

**Time:** a few minutes on the first run, almost all of it dependency installation; later
runs take about 30 s. No GPU, network testbed, Docker, or root is needed. Figures 3–4 are
regenerated byte-identical to the committed PDFs, so the working tree stays clean.

For the **Reproduced** badge, the live experiments run on the evaluator's own machine; see
[Hardware for the Reproduced badge](#hardware-for-the-reproduced-badge).

The same script also drives the live reproductions:

| Command | Purpose | Needs |
|---|---|---|
| `./run_artifact.sh env` | hardware and software readiness report for the live tracks | — |
| `./run_artifact.sh live-ueransim` | Track B: Docker testbed, `run_experiments.sh --phase all` (≈ 38 h), then `reproduce_results.py --fresh` (claim-level comparison with the paper) | Docker; local Ollama GPU with the paper models |
| `sudo ./run_artifact.sh live-srsran` | Track C2: the srsRAN radio measurements and LLM experiments listed in the [one-day plan](#artifact-evaluation-plan-fits-in-one-day) (≈ 5–6 h), then `verify_paper.py --fresh` | root; srsRAN build; GNU Radio |
| `sudo ./run_artifact.sh all` | all of the above in sequence | all of the above |
| *any mode* `--dry-run` | print the plan and prerequisite checks without executing anything | — |

Live modes **back up the stored results before overwriting them** (to
`artifact_logs/backup_*.tar.gz`). For srsRAN, pass the build location through `sudo`:
`sudo --preserve-env=SRSRAN_BUILD,ANTHROPIC_API_KEY ./run_artifact.sh live-srsran`.

The sections below describe each track in detail, for evaluators who want to run stages
individually.

UERANSIM subtotal ≈ 16 h; with the srsRAN track ≈ 21–22 h. Run the srsRAN track after the
UERANSIM runs rather than alongside them, since both use the same GPU.

The srsRAN track first moves the stored LLM checkpoints
(`srsran/results/llm_trials/{E3,E5,E6}`) aside so every trial re-runs, and its final stage
(`analysis/verify_paper.py --fresh`) **fails** if the fresh results do not support the
paper's claims. It does not run E9, E2, E2.3, E0.5 or E12/E12b; their stored results are
verified offline in step 1. The §6.3 UERANSIM target share (71.4%) is analytical — it is
computed from the testbed's shaper model, not re-measured by a fresh run.

Each phase **moves the stored results of the experiments it runs to
`artifact_logs/stored_<timestamp>/`** before starting, so every trial really re-runs (the
scripts otherwise resume from the stored checkpoints and would re-read the stored data),
and afterwards **replaces `final_experiments/<exp>` with the fresh results** (the stored copy
stays in `artifact_logs/stored_<timestamp>/final_experiments/`) and writes a `FRESH_RUN`
marker there; `reproduce_results.py` reads them. An interrupted phase continues with `--resume`. The
phases reuse the stored k†\* calibration (`wave_experiments/results/exp6/kstar.json`);
`--phase calibrate` recalibrates it (Exp 6 phase 1).

The remaining UERANSIM experiments — the rest of `--phase rq4` (Exp 6 phases 2–3, Exp 7
adaptive prompts 7.7 h, Exp 15) and `--phase rq5` (Exp 8, 10, 13; ≈ 7.8 h) — do not fit the
one-day budget; their stored results are verified in step 1. In the srsRAN track the E6
frontier tier (Claude Sonnet 4.5) needs a paid `ANTHROPIC_API_KEY` and is skipped without
it; the local E6 tiers still run.

**Judging fresh runs.** Without `--fresh`, `reproduce_results.py` checks the stored logs at
the paper's printed precision (±0.5 pp). With `--fresh` it judges each proportion by a
two-sided Fisher exact test of the fresh count against the paper's count (pass if
p > 0.05; a ±10 pp window on n = 20–30 would reject a correct system most of the time),
requires p < 10⁻⁴ for the oversight tests, keeps the ordering claims, and requires the
Table 10C escape rate to decrease from 100%. It prints which experiments carry a
`FRESH_RUN` marker (i.e. were re-run) and labels the checks that come from stored results
because the one-day plan does not rerun them (Exp 6, 7, 15 and RQ5).
`./run_artifact.sh live-srsran` judges the fresh srsRAN results itself with
`analysis/verify_paper.py --fresh`, which applies claim-level criteria (20 claims):
deterministic E4/E5/E8 results must match exactly, the E3/E6 LLM counts are compared with
the paper's counts by Fisher exact test, and the radio measurements must meet the paper's
claims (E1 capacity 22.8 Mbps ± 10%, victim λ inflation > 1.5× (paper 1.95×), victim τ flat
(5.43 Mbps ± 10%); E0.4 target share > 86% (paper > 91%); E10 overhead < 1.3 ms).

`./run_artifact.sh live-ueransim` runs `run_experiments.sh --phase all` (≈ 38 h of
experiments), which exceeds the one-day budget; use the per-phase commands above instead.

### Step 3 — One-Command Testbed Setup

```bash
chmod +x quickstart.sh
./quickstart.sh
```

This interactive script handles everything:
1. Checks Docker, Docker Compose, Python and sudo
2. Prompts for the LLM backend choice and API key (writes `.env`)
3. Creates the Python virtual environment and runs the one-time host setup
4. Builds the Docker images (first run: ~15 min; includes UERANSIM v3.2.7 compiled from upstream source)
5. Starts the 16 services: MongoDB (+ one-shot subscriber init), Open5GS NFs (NRF, SCP, AMF, SMF, UPF, PCF, UDM, UDR, AUSF, NSSF, BSF, WebUI), UERANSIM (one container running the gNB and one UE; 10 subscribers are provisioned), NWDAF collector
6. Applies HTB traffic shaping on loopback (15 Mbps cap / 40ms delay / 3% loss) for Q measurement (the ground-truth probe also installs its own shaper at the start of every trial)
7. Offers to run Track A as a sanity check on stored results

**Other modes:**
```bash
./quickstart.sh --testbed-only    # start Docker stack only (already configured)
./quickstart.sh --offline-only    # run Track A only
./quickstart.sh --status          # check all services
./quickstart.sh --stop            # stop and clean up
```

### Step 4 — Verify Testbed Health


**PALA system tuple S = (A, H, O, D, C, Φ):**

| Component | Paper def. | Implementation | §|
|-----------|-----------|----------------|---|

**How the UERANSIM testbed realises AMBR over-subscription.** UERANSIM has no radio
scheduler, so the main testbed realises over-subscription at a host bottleneck (§6.3):
`QProbe.update_tc_for_ambr` in `wave_experiments/shared/probe.py` scales the HTB shaper
rate by baseline/B for a newly written AMBR B (floor 1 Mbps). When iperf3 returns no
measurement, the probe records throughput as 0.9 × the current shaper rate; 377 of the 382
stored exp1 τ samples lie on this shaper model (`reproduce_results.py` prints this as a
NOTE). Φ on this testbed therefore measures the shaper model, not radio contention; the
srsRAN track (Track C) is the radio-side validation of the same mechanism with a real
scheduler as the bottleneck.

## Three Architectural Failure Surfaces (Theorem 5)

| ID | Property | Standard behaviour | Defense |
|----|----------|-------------------|---------|
| AS2 | Provenance-free collector aggregation | C writes Type-P fields into D_ana without semantic labels | **IsolatedCollector**: tags every field φ ∈ {T,P}, filters φ=P before D_ana write |
| AS4 | Stateless per-call feasibility | H_feas checks each δᵢ in isolation; no session accumulator | Not removed — AS4 is individually defensible; circuit requires AS2+AS4+AS6 jointly |
| AS6 | Per-call oversight scope | O reviews (F(δᵢ),δᵢ,sᵢ) locally; cannot see session trajectory | **HedgeTuned H_budget**: stateful session counter, rejects at step i > k†* |

**Guardrail composition (Theorem 8):** IsolatedCollector severs the AS2 contamination link; H_budget severs the AS6 escalation link. Combined, 0/50 operational closures (§6.5).

## Security and Scope

All experiments use an isolated Open5GS testbed with synthetic subscribers only (IMSI range `999700000000001`–`999700000000010`, from `docker/testbed/scripts/init_subscribers.js`). No production carrier infrastructure is involved. The paper studies endogenous reward hacking arising from authorised use of standards-compliant NWDAF interfaces by a frozen, non-malicious agent with benign operator intent. Excluded from scope: prompt injection, compromised tools, physical-layer interference, malicious operators. See §3.3 (System Assumptions) and Appendix D (Threat Scope) of the paper.
